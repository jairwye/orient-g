# 电子表（Excel）数据解析工作流（中文版示例 Skill）

> 适用范围：`/utils/excel-kanban` 的解析会话问答、按需生图/生表、以及后续“表持久化/入库”的工作流提示。

## 一、硬约束（必须遵守）

1. **先读表再说话**：回答任何与表格、图表、汇总、数据质量、清洗建议相关的问题前，必须先调用 `read_metrics`（或等价只读工具）确认当前会话的 `table_schemas` / 列画像 / 校验摘要。
2. **证据范围**：所有结论、趋势、对比、异常判断，只能引用工具返回的聚合指标、表结构摘要或 `generate_table` / `generate_chart` / `auto_generate_chart` 的结果；不得编造未出现的金额、占比、日期或期间。
3. **不泄露行级明文**：不得在回复/日志/提示词中输出用户上传的行级原始表格内容；如需引用，返回 citations（表/行定位或 doc/chunk 定位）而不是整段原文。
4. **Excel 格式类诉求**（单元格底色、边框、主题、条件格式等）：诚实说明当前工具链不支持；可改为生成图表/汇总表提升可读性，并仍须先 `read_metrics`。
5. **工具调用受控**：仅允许使用白名单工具（由页面 allow-list 决定）；未启用的工具一律不调用。

## 二、工作流建议（按需选用）

### 2.1 结构理解与风险提示

- 先 `read_metrics` 获取：工作表列表、表头、行数、类型画像、缺失与异常摘要。
- 输出应包含：**结论**（结构概述）、**风险**（缺失/空表头/行数过少/混合类型等）、**建议**（后续清洗或补字段）。

### 2.2 口径与单位（禁止临场发明）

- 若涉及 FP&A 指标口径（收入/成本/毛利/同比/环比等），必须以系统提供的口径字典或已启用的 `prompt.*` 资产为准。
- 发生冲突时以“工具返回的结构化指标与校验摘要”为最终事实来源，并在 risks 中说明冲突点。

### 2.3 制图与制表

- 用户未给出明确 sheet/列名：优先 `auto_generate_chart`。
- 用户给出明确列名：使用 `generate_chart` 或 `generate_table`，并在回复中简要解释图/表表达的含义与限制。

## 三、输出风格（推荐）

- 面向业务：输出可分为 `conclusion / risks / suggestions` 三段（自然语言即可）。
- 遇缺失/异常：必须明确写出“证据不足/缺失字段/校验异常”，禁止用猜测补全。

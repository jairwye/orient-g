## 1. 背景与目标

### 1.1 现状

- 侧栏已有 **竞品财报**（`DashboardLayout` → `/competitor`），当前为占位页。
- 知识库 **竞品财报25** 文件夹 + Agent Skill `skill.finance.annual_report.v1` 已支撑 **问答/对比/附注检索**，与本特性 **互补**：Agent 回答 ad-hoc 问题；本页提供 **固定版式、可浏览的行业汇析仪表盘**。
- 财务后台已有「经营数据 Excel」「股权 bundle.zip」上传范式；**竞品财报汇析 MD** 为财务后台内 **新增第四块上传区**（与前三块并列，见 §7）。
- 财务后台 URL 可由 `settings.finance_path` 配置为自定义单段路径；**上传解析逻辑与展示入口均不依赖 URL 字符串**（见 §1.4）。

### 1.2 目标（v1）

1. 管理员在 **财务后台**（任意有效 `finance_path`）上传 **内容蓝本 Markdown**（`.md`）。
2. 后端校验并解析为结构化 **Report Snapshot**（JSON），持久化；**生效展示**固定对应侧栏 **竞品财报**（`/competitor`）。
3. **管理层 / 财务部 / 管理员**（具备 `view_business_dashboard`）从侧栏 **竞品财报** 进入，加载最新 Snapshot，渲染 **9 屏 scroll-snap 交互分析页**（Recharts + 自定义 SVG；`sec-09` 含 `sec-09-10`～`sec-09-15` 细节补充子锚点）。
4. 数据 **100% 来自上传 MD**，禁止前端/LLM 编造数值；解析失败须给出可修复的错误清单。

### 1.3 非目标（v1）

- 不从 KB 年报 PDF 自动抽取生成 MD（仍由财务/分析岗维护蓝本）。
- 不替换 Agent 竞品财报工作流；不在本页嵌入 Hermes 对话（可二期加「带到 AI 内网」深链）。
- 不做多版本并行对比 UI（v1 仅「当前生效」+ 上传覆盖；历史 raw 文件可保留审计）。
- 不引入外网 CDN、第三方图表 SaaS。

### 1.4 财务后台路径（`finance_path`）与上传绑定

| 项 | 约定 |
|----|------|
| 页面实现 | 唯一 React 页面 `frontend/app/finance/page.tsx`（canonical `/finance`） |
| 自定义路径 | 管理员在财务后台内将 `finance_path` 改为如 `/finance_ops` 时，`frontend/middleware.ts` 将 **该路径 rewrite 到 `/finance`**，浏览器地址栏仍为自定义路径 |
| 默认路径关闭 | 自定义路径生效后，直接访问 `/finance` 返回 **404**（middleware + AuthGuard 一致） |
| **竞品财报上传** | 在 **财务后台页面内** 新增 card；无论用户从 `/finance` 还是 `/finance_ops` 进入，均调用同一 API，解析结果 **唯一写入** 侧栏「竞品财报」数据源 |
| 与 `finance_path` 无关 | `POST /api/competitor/admin/upload` **不得**把路径名编入存储键或路由；Snapshot 全局单例 `{upload_dir}/competitor/report.snapshot.json` |
| 内链 | 空态/成功提示链向财务后台时使用 `useAuth().finance_path`（或 `/api/auth/me` 的 `finance_path`），**禁止**硬编码 `/finance` |

> **修复说明（2026-06）：** 此前 `frontend/proxy.ts` 未启用为 middleware，导致自定义 `finance_path` 不生效；已启用 `frontend/middleware.ts`。

### 1.5 权限（RBAC，对齐 [`1.2.0.a-权限模型与页面可见性.md`](1.2.0.a-权限模型与页面可见性.md)）

| 能力 | 权限 | 主体 |
|------|------|------|
| 侧栏「竞品财报」可见、进入 `/competitor` | `view_business_dashboard` | **管理层**、**部门=财务部**、**管理员** |
| `GET /api/competitor/report`、`/summary`、`/report/meta` | `_require_view_business_dashboard` | 同上 |
| 财务后台上传 MD | `_require_admin` | **仅管理员**（与 `POST /api/business/upload` 一致；与 `finance_path` 无关） |

- 普通已鉴权用户（非管理层/非财务部/非管理员）：**不可见**侧栏入口、**不可**直接访问 `/competitor`（AuthGuard 重定向至 `/ai-interaction`）；对应 GET API 返回 **403**。
- 上传与展示分离：财务部可看分析页但**不可**进财务后台上传；上传仅管理员在财务后台第四块 card 完成。
- **图表库**：Recharts 2.x，与现网经营数据页 `BusinessDashboard` 一致（规划总纲 §4.2 已同步为 Recharts，非初稿 ECharts）。
- **审计**：上传成功须记录 `uploaded_by`、`uploaded_at`、`source_filename` 于 Snapshot `meta`；可选 `{upload_dir}/competitor/history/` 保留 raw 副本。
- **备份**：`{upload_dir}/competitor/` 纳入 uploads 目录既有备份策略（见 `规则/规则.md`、运维手册）。
- **本地开发（蓝本预览）**：未上传 Snapshot 时，若 `COMPETITOR_FIXTURE_FALLBACK` 未显式设置且 `APP_ENV=development`，API 按需解析 `backend/tests/fixtures/competitor_report_minimal.md`；**生产环境须关闭回退**，未上传时返回 404。完整 YYCQ 蓝本仅保留在 `uploads/`（不入库），由财务后台上传生效。

## 2. 内容蓝本约定

### 2.1 文档结构

蓝本示例：`uploads/行业财报汇析-2025年_数据文档_YYCQ版.md`

| 约定 | 说明 |
|------|------|
| 章节锚点 | `sec-01` … `sec-09`（标题中含锚点 id）；`sec-09` 扩展子锚点 `sec-09-10`～`sec-09-15`（细节补充，非独立第 10 屏） |
| 子锚点 | `sec-XX-N`（如 `sec-03-1`），对应屏内图表模块 |
| 公司列 | **8 家**：游艺春秋（YYCQ）+ 7 家可比公司；列序以 MD 表头为准 |
| 金额单位 | 万元（文档元数据声明；解析时写入 snapshot.meta） |
| 分析段落 | 加粗/普通 prose 映射为 `narrative` 字段，供侧注/折叠面板 |

> **与工程参考差异：** 参考稿按 7 家公司编写；YYCQ 版为 8 家且部分表格存在 **双值粘连**（如 `5698 289,895`）、`|` 写成 `||` 等笔误。解析器须 **容错 + 校验报告**，不以参考稿为唯一 schema。

### 2.2 章节与屏映射（与参考稿对齐）

| 屏 | 锚点 | 标题 | 主图表（v1 优先） |
|:--:|------|------|-------------------|
| 1 | sec-01 | 行业总览 | 营收-净利气泡图、KPI 卡、商业模式卡 |
| 2 | sec-02 | 综合排名 | 排名条形图、雷达图 |
| 3 | sec-03 | 经营成果 | 小多图趋势、象限散点 |
| 4 | sec-04 | 人员与人效 | 人员结构堆叠条、人效散点 |
| 5 | sec-05 | 主营收入成本 | 桑基/分组柱（可分期）、毛利率对比 |
| 6 | sec-06 | 资产负债表 | 资产环形、杜邦条形 |
| 7 | sec-07 | 利润表 | 费用率堆叠、趋势折线 |
| 8 | sec-08 | 现金流量表 | 现金流瀑布、CF/净利仪表 |
| 9 | sec-09 | 其他重要事项与细节补充 | 风险/ROI、附录表；**含** `sec-09-10`～`15`（游戏/客户/关联方/R&D 等 Explorer） |

> **2026-06 蓝本对齐：** YYCQ 版将原工程参考中的独立 `sec-10 风险与附录` **并入** `sec-09` 子锚点，前端为 **9 屏** 主导航；解析器要求 `sec-01`～`sec-09`，并对 `sec-09-10`～`15` 缺失给出 warnings。

### 2.3 标题层级容错

蓝本中 `sec-07`/`sec-08`/`sec-09` 可能以 `###` 出现在 `sec-06` 之后。解析器以 **锚点正则** `^#{1,3}\s+(sec-\d{2}(?:-\d+)?)\b` 识别，**不依赖** `#` 层级推断父子关系。

## 3. 方案选型（Superpowers 脑暴结论）

### 方案 A — 上传 MD → 服务端解析 → API 驱动前端（**推荐**）

- 财务后台上传 `.md` → `POST /api/competitor/admin/upload`
- 解析为 JSON Snapshot 存盘（+ 保留 raw MD）
- `/competitor` 通过 `GET /api/competitor/report` 渲染

**优点：** 与经营数据 Excel 一致；满足「后台上传即生效」；可单测解析器。  
**缺点：** 需维护 MD schema 与容错逻辑。

### 方案 B — 构建时静态 `report-data.ts`

**否决：** 无法满足运行时上传。

### 方案 C — 上传 MD 后 LLM 生成页面代码/JSON

**否决：** 违背内网数据确定性、可审计要求；与《规则》禁止编造冲突。

**决策：采用方案 A。** v1 解析在 Python 后端完成（与现有 FastAPI 栈一致）；前端只做展示与交互。

## 4. 数据模型（Snapshot v1）

```typescript
type CompetitorReportSnapshot = {
  version: 1;
  meta: {
    title: string;           // 如「行业财报汇析 — 2025年」
    period: string;          // 2025
    currency_unit: "万元";
    company_count: number;
    source_filename: string;
    uploaded_at: string;     // ISO
    uploaded_by: string;
    parser_version: string;
  };
  companies: Array<{
    id: string;              // 稳定 slug，如 "yycq" | "37" | "完美世界"
    label: string;           // 显示名：游艺春秋 / 三七互娱 / …
    short?: string;          // YYCQ
    color?: string;          // 可选；缺省走 UI 色板
  }>;
  sections: Array<{
    id: string;              // sec-01 … sec-09
    title: string;
    blocks: Array<
      | { kind: "table"; anchor: string; headers: string[]; rows: Record<string, string | number | null>[] }
      | { kind: "narrative"; anchor?: string; markdown: string }
      | { kind: "kv"; anchor: string; items: Record<string, string> }
    >;
  }>;
  warnings: string[];        // 非阻断解析告警
};
```

- 图表组件从 `sections[].blocks` 按 **anchor** 取数，不硬编码 doc_id。
- 数值列统一解析为 `number | null`（无法解析则 `null` + warning）。

## 5. API 契约

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| POST | `/api/competitor/admin/upload` | `_require_admin`（同 `/api/business/upload`；**与 `finance_path` 无关**） | `multipart/form-data`：`file`（.md）；成功即更新 **竞品财报** Snapshot |
| GET | `/api/competitor/report` | `_require_view_business_dashboard` | 返回当前生效 Snapshot；无数据时 `404` + `{ detail: "no_report" }` |
| GET | `/api/competitor/summary` | `_require_view_business_dashboard` | 轻量 meta（`updatedAt`、标题、公司数） |
| GET | `/api/competitor/report/meta` | `_require_view_business_dashboard` | 仅 meta + warnings（轻量探活） |

**上传响应：**

```json
{
  "ok": true,
  "meta": { "title": "…", "uploaded_at": "…" },
  "warnings": ["sec-01-2 row 3: split dual value YYCQ/三七互娱"],
  "sections_parsed": 10
}
```

**存储路径（建议）：**

- Raw：`{upload_dir}/competitor/report.md`（覆盖写）
- JSON：`{upload_dir}/competitor/report.snapshot.json`
- 可选审计：`{upload_dir}/competitor/history/{timestamp}_{filename}`

## 7. 财务后台（新增上传区）

在 `frontend/app/finance/page.tsx` 增加 **第四块** card（与经营 Excel、股权 bundle、路径设置并列）：

- 标题：**上传竞品财报汇析（Markdown）**
- 说明：上传后将解析为侧栏 **「竞品财报」** 分析页数据；**与当前财务后台 URL 路径无关**
- 接受 `.md`，调用 `POST /api/competitor/admin/upload`
- 成功：展示 warnings 列表 + 「打开竞品财报页 →」链到 **`/competitor`**（展示入口固定）
- 失败：展示 parser 错误行号/锚点

**验收：** 将 `finance_path` 改为非 `/finance` 后，从新路径进入财务后台，上传 MD 仍可在 `/competitor` 看到结果。

## 8. 解析器（后端）

- 新模块：`backend/services/competitor_report_parser.py`
- 职责：
  1. 读取 MD，按锚点切 section
  2. 提取 GFM 表格 → 行对象
  3. 公司列识别（表头含 YYCQ/游艺春秋/三七互娱…）
  4. 数值清洗：去千分位、百分号、括号负号、**双值拆分启发式**
  5. 输出 Snapshot + warnings/errors
- 阻断错误（HTTP 400）：缺少 `sec-01`~`sec-09` 任一、零表格、文件非 UTF-8；`sec-09-10`～`15` 缺失仅 warnings

**测试：**

- `backend/tests/test_competitor_report_parser.py` — 使用仓库内 `uploads/行业财报汇析-2025年_数据文档_YYCQ版.md` fixture（或 `backend/tests/fixtures/` 副本）
- 断言：10 sections、8 companies、关键 anchor 行数、无未处理 dual-value

## 10. 验收标准（v1）

1. 在 **财务后台**（含自定义 `finance_path` alias）上传 YYCQ 版 MD 成功后，`/competitor` 可加载且 **9 屏可 scroll-snap 导航**（`sec-09` 含细节补充子锚点）。
2. sec-01、sec-02 图表数值与 MD 表一致（抽样 ≥5 个 KPI 人工核对）。
3. ~~8 家公司全局筛选器生效（高亮选中、其余降透明度）。~~ **v1 已取消**（见 plan Task 16）；v2 再评估。
4. 未上传时占位页引导明确；非 `view_business_dashboard` 用户不可见侧栏入口且 GET API 403；非管理员无法调用 upload API（403）。
5. 解析 warnings 在上传成功响应、财务后台 UI 与 **竞品页顶部告警区** 可见（fixture 预览时展示 data_source 提示）。
6. 单元测试 + 至少 1 条集成测试（upload → GET report）CI 可跑。

## 11. 风险与缓解

| 风险 | 缓解 |
|------|------|
| MD 笔误/粘连导致错数 | warnings + 上传前校验摘要；财务二次确认 |
| 9 屏 + sec-09 子模块工作量大 | 分三期交付（见 plan）；每屏可降级为「表格 + 单图」 |
| 桑基/旭日 Recharts 不原生 | 参考工程稿：d3-sankey / CSS grid 热力；v1 可简化为堆叠柱 |
| 大文件性能 | 懒加载 section（IntersectionObserver + dynamic import） |

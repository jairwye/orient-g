# 2.a Orient-G 2.0：权限模型与页面可见性规划（Hybrid：RBAC + ACL）

## 范围

- 仅规划 **页面可见性** 与 **默认首页路由策略**（RBAC 层）。
- 知识库对象模型与 ACL 规则由 `2.b/2.d` 定义；本步与定稿方案对齐（管理层/管理员 + 部门·项目维度）。
- 明确 2.0 需要新增/调整的页面分类与拆分边界：
  - 功能2「文档处理/导入」归入「实用工具」页。
  - 新增「AI互动」页，并作为“无经营数据页权限用户”的默认首页。
  - 将现「管理后台」拆分为「财务后台」与「管理后台」两页。

## 交付物

- `角色/属性-页面` RBAC 页面矩阵（可验收）。
- 页面清单（逻辑名 → 路由占位 → 权限点）。
- 默认首页路由策略（基于权限点 `view_business_dashboard`）。
- 拆分后的「财务后台 / 管理后台」职责边界（用于后续接口/路由落地与验收）。

## 角色与主体属性定义（RBAC 口径）

> 角色与组织属性用于决定“能不能看到/进入某页”。内容检索与文档访问由 ACL 决定，属于 `2.b/2.d` 交付物。

**顶层角色（可确定）**：

- **管理层**：仅展示端与经营数据查看，不进入后台。
- **管理员**：系统与后台管理（用户管理、系统设置、观测/队列等）；**默认拥有** `view_business_dashboard`（可进经营数据页，便于运维排查）。

**组织属性（非角色，用于页面与知识库授权）**：

- **财务部**：定义为部门属性 `department=财务部`（或等价 `department_id` 对应财务部）。拥有经营数据页可见/可进入、财务公共知识库等权限，与“财务后台”区分（财务后台仅管理员可进）。
- **部门 / 项目**：其余业务用户纳入部门、项目维度；部门负责人、项目负责人为 ACL 主体属性，见 `2.b`。

**页面权限点（本步使用）**：

- `view_business_dashboard`：经营数据页（首页/根路径）可见且可进入。
- `view_admin_finance`：财务后台可见且可进入。
- `view_admin_management`：管理后台可见且可进入。
- 其他页面（知识库、实用工具、数据解析、AI互动）：本步默认对所有已鉴权用户可见/可进入；若未来收紧，再增权限点并与矩阵一致。

**授予规则（权威来源为 PostgreSQL，见定稿方案）**：

- `view_business_dashboard` 授予：**管理层** 或 **管理员** 或 **部门=财务部**。
- `view_admin_finance`、`view_admin_management` 仅授予：**管理员**。

## 页面清单（RBAC 可见性口径）

本项目页面在 2.0 采用如下逻辑体系（路由占位仅用于本步验收描述，最终以实现为准）：

| 逻辑名 | 建议路由占位 | 权限点 |
|--------|--------------|--------|
| AI互动 | `/ai-interaction` | （默认可进入，作为无经营数据权限时的默认首页） |
| 首页/经营数据 | `/` | `view_business_dashboard` |
| 知识库 | `/knowledge` | （默认可进入；内容由 ACL 过滤，见 2.b/2.d） |
| 实用工具（含功能2） | `/utils`，功能2 子页 `utils/process-doc` 或等价 | （默认可进入） |
| 数据解析 | `/utils/excel-kanban` 或等价 | （默认可进入） |
| 财务后台 | `/finance`（可配置，proxy 将配置路径 rewrite 至该路由） | `view_admin_finance` |
| 管理后台 | `/admin`（固定） | `view_admin_management` |

## 默认首页路由策略（RBAC）

- 规则：首次进入或访问根路径 `'/'` 时，根据权限决定落点。
  1. 若用户拥有权限 **`view_business_dashboard`**：默认进入 **首页/经营数据**（根路径 `/`）。
  2. 否则：默认进入 **AI互动**（如 `/ai-interaction`），不展示经营数据页入口。

## RBAC 页面矩阵（可验收的“能看见/能进入”）

> 下面以“路由能进入/侧边栏出现/重定向是否正确”为验收依据。**后端须对对应 API 做强制鉴权**，不信任前端；前端仅负责体验层显隐与跳转。

| 主体类型 | AI互动 | 首页/经营数据 | 知识库 | 实用工具 | 数据解析 | 财务后台 | 管理后台 |
|----------|--------|----------------|--------|----------|----------|----------|----------|
| 普通用户（已鉴权，非管理层/非管理员/非财务部） | 可见/可进入 | **不可见/不可进入**（重定向至 AI互动） | 可见/可进入（内容依 ACL） | 可见/可进入 | 可见/可进入 | **不可见/不可进入** | **不可见/不可进入** |
| 管理层 | 可见/可进入 | 可见/可进入 | 可见/可进入 | 可见/可进入 | 可见/可进入 | 不可见/不可进入 | 不可见/不可进入 |
| 部门=财务部（非管理员） | 可见/可进入 | 可见/可进入 | 可见/可进入 | 可见/可进入 | 可见/可进入 | 不可见/不可进入 | 不可见/不可进入 |
| 管理员 | 可见/可进入 | 可见/可进入 | 可见/可进入 | 可见/可进入 | 可见/可进入 | 可见/可进入 | 可见/可进入 |

注释（验收口径对齐）：

- “内容依 ACL”指知识库检索与展示由 `2.b/2.d` 的 ACL 过滤；本步只验页面能否进入。
- 管理员默认拥有 `view_business_dashboard`，与上表一致；若实现选择“管理员仅后台不进经营数据页”，则需同步修改本矩阵与验收条款。

## 财务后台 / 管理后台 拆分职责边界（本步确定）

- **财务后台** 负责（可客观验收的功能集合）：
  - 经营数据 Excel 上传与导入触发。
  - 入口路径调整（财务后台路径可配置，默认 `/finance`，可改为其他单段路径并由 proxy rewrite）。
  - 经营数据导入相关的参数/元数据维护（如月份/期间选择、导入核查项的展示）。
  - 与“管理员身份”绑定的鉴权（仅管理员可进入）；财务部成员可看经营数据页但不可进财务后台。
- **管理后台** 负责（可客观验收的功能集合）：
  - 用户管理（新增/删除/重设密码/禁用等）。
  - 组织与权限：部门、项目、成员关系、负责人绑定、顶层角色（管理层/管理员）绑定。
  - 系统设置与安全配置（例如启用页面登录、审计配置入口等）。
  - 观测与运维相关的管理能力（队列、失败率、告警阈值等，后续在 `2.e` 详细定义）。

## 验收标准（本步必须满足的客观检查清单）

- **默认首页**：
  - 未具备 `view_business_dashboard` 的用户，访问 `'/'` 须被重定向/落点到 **AI互动**。
  - 具备 `view_business_dashboard` 的用户，访问 `'/'` 须正常进入 **首页/经营数据**。
- **页面可见性**：
  - 每个用户登录后，侧边栏/路由入口只显示其允许的页面集合（与上表 RBAC 页面矩阵一致）。
- **权限拒绝行为**：
  - 直接访问“不该进入的页面路由”（如手动输入财务后台/管理后台 URL），须返回 **403 或等价跳转**，不得展示该页业务内容；**后端对应 API 须强制鉴权**。
- **分类正确性**：
  - 功能2「文档处理/导入」在 UI 中属于「实用工具」体系（从实用工具聚合页可达）。
  - 存在独立「AI互动」页面入口（或至少通过默认路由可落到 AI 互动 UI）。

## 实现与验收状态（与当前代码对齐）

- **默认首页**：已实现。AuthGuard 在鉴权后根据 `view_business_dashboard` 决定访问 `/` 时是否重定向至 `/ai-interaction`；侧栏「经营数据」仅在有该权限时展示。
- **页面可见性**：已实现。侧栏由 `view_business_dashboard`（经营数据）、`is_admin`（管理后台）控制；财务后台无侧栏入口，仅管理员从管理后台页内链接可达，且访问任意配置路径时由 AuthGuard 按 `finance_path` + `is_admin` 拦截。
- **权限拒绝**：已实现。直接访问 `/`、`/admin`、财务后台配置路径时，无权限用户被重定向至 `/ai-interaction`，且先展示「正在跳转…」避免页面一闪而过。
- **后端鉴权**：经营数据 `GET /api/business/overview`、`GET /api/business/summary` 使用 `_require_view_business_dashboard`；`POST /api/business/upload` 与 `GET/PATCH /api/settings` 等使用 `_require_admin`。`/me` 返回 `view_business_dashboard`、`finance_path` 供前端使用。
- **分类正确性**：实用工具聚合页 `/utils` 含流程文档、PDF 知识库、数据解析等入口；侧栏有「AI 互动」且为无经营数据权限时的默认落点。

## 风险与依赖

- **依赖 `2.b/2.d`**：知识库页面“可见/可进入”后的内容安全由 ACL 与 pre-filter 保证；本步只保证页面可进入性。
- **用户与组织权威存储**：用户、部门、项目、角色绑定等以 PostgreSQL 为权威（见权限方案定稿）；运行时配置可仍用文件。
- **当前代码迁移**：现有 `'/admin'` 若混合财务与管理能力，2.0 须按本步职责拆分，并按本矩阵收紧可见性。
- **安全**：若启用页面登录与会话管理，须符合内网/鉴权/审计要求（如 week0-security-checklist.md）。

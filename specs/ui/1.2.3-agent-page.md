## 3. API

- `POST /api/agent/chat`（经 backend 调 Hermes，见规制 §5 演进）
- 请求含：`messages`、`kb_scope`、`attached_doc_ids`、`allow_kb_write`（默认 **true**）、`hermes_session_id?`、`agent_mode`（`fast` \| `standard` \| `deep`）
- 后端经 **内网 HTTP** 调 Hermes（非浏览器执行 CLI）；`tool_calls` 可含沙盒内 `lark`、`searxng` 等（二期、开关控制）

## 4. 与 AI 互动的分工

| 页面 | 用途 |
|------|------|
| `/ai-interaction` | 日常问答、工作空间（bigpdf/提示词）、标准 RAG + Skill 勾选 |
| `/agent` | 长链自动化、多工具、KB 读写、飞书/搜索（开关开时） |

工作空间可从 Agent 页 **带入 scope**（URL 参数，同 `kb_scope_capsule` 约定）。

## 5. 停止 / 取消（现状与风险）

| 动作 | 实际效果 |
|------|----------|
| 前端「停止」`AbortController.abort()` | 断开浏览器到 Orient-G 的 **SSE**；不再收 delta |
| `POST /api/agent/cancel` + `X-Agent-Run-Id` | 设置内存 `agent_run_registry` 取消标志 |
| Hermes 路径 | 流式循环中轮询 `is_cancelled`，可停止**继续向前端推流**；已发出的 Hermes/MCP HTTP 请求**未必立即中断** |
| **快速路径（本地 LLM 综合）** | `synthesize_kb_reply` **未**检查 `run_id`；取消后 **LLM 仍可能跑满**（阻塞 HTTP，最长约 240s），GPU/CPU 占用持续 |
| 离开页面 / 关标签 | **无** `useEffect` 卸载时自动 `abort`+`/cancel`；后端任务可能继续直到超时结束 |

**现象解释：** 显卡空闲但 CPU 仍高，常见于快速路径下 LLM 推理落在 CPU、或 Hermes/Ollama 请求未真正 abort。

**目标（待实施，见 [`features/1.2.3-agent-kb-router-design.md`](../features/1.2.3-agent-kb-router-design.md) 后续任务）：** 快速路径传 `run_id` 并在合成前/流式分块中检查取消；页面 `beforeunload` 与路由离开时调用 cancel；可选 httpx 请求 cancel（需 LLM 网关支持）。

# 1.2.0.d 回答审计 + 1.2.0.c 文档状态机 — 实施计划

> **Goal:** `/api/ai-interaction/chat` 与 `/api/knowledge/ask` 共用同一套 RAG 审计事件；通用上传文档经 `kb_doc_lifecycle` 校验状态迁移并写入标准 manifest 字段。

**Architecture:** 新增薄服务层 `rag_audit_bridge`（封装 `knowledge_audit.write_event`）与 `kb_doc_lifecycle`（状态枚举 + 合法迁移）；路由层只调 bridge，不散落 SQL/事件名。manifest 仍由 `kb_documents._parse_and_package_document` 生成，经 lifecycle 落库。

**Tech Stack:** FastAPI、SQLAlchemy raw SQL、pytest、现有 `kb_audit_events` 表。

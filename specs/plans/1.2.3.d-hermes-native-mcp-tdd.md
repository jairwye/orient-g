## 0.1 Done 定义（kb_scope ⇒ 最大化 MCP · 硬尺子）

**前提**：用户选了知识库（`kb_scope` 非空）。

终稿与链路算 **构想达成** 当且仅当 **同时** 满足：

### A. 编排与出处

1. `reply_source == "hermes"`（done SSE / probe / CDP）
2. `structured_gate_applied == false`（structured final gate **未**整页替换）
3. `kb_supplemental == false`（native skip 路径；或 supplemental 未采纳且正文仍为 Hermes）
4. native+deep 人员：`gateway_orientg_kb_ask_calls ≤ 2`（目标 slim）
5. **禁止** OG structured / misattribution 整页模板冒充主写；**禁止** Evidence Pack 空转先出稿再靠 retry 补 MCP

### B. 工具环（硬项 · 禁止 retry 刷绿）

1. **首轮 Runs 即调用** `orientg_kb_ask`——`hermes_mcp_retry_count == 0`（**硬失败**若 >0）
2. Live / Probe / CDP：**不得**出现「Hermes 未调用 orientg_kb_ask，发起 MCP 优先重试」成功路径当验收绿
3. **`hermes_mcp_retry` 凑满 ×2 不算充分利用 KB**——即便最终 `hermes_orientg_kb_ask_calls ≥ 2`，只要 `retry_count > 0` 即 **FAIL**
4. 网关 `hermes_mcp_retry` 仅保留为异常保险丝；验收常态必须为 0

### C. 终稿质量（硬项）

1. 主气泡须有「人员结构对照」+ 关键锚点（1378/70，及证据足时的 946/242）
2. **禁止上屏**：推算 / 推断 / 推测 / 「约 xx 人」/「~N人」（无证据区间）/ 无依据扩写
3. 不得靠脚注「请勿采信」掩盖仍展示的违规句
4. 若过程稿 / 正文流已有更合规对照表+分析（含锚点），**质量择优必须保住它**
5. **主气泡不得以「成稿骨架」/「请原样采用下列数字写入终稿」为终稿**（MCP 工具结果内可作数字参考；上屏须完整中文终稿）
6. **禁止**将 139（华清/可比公司E 在职规模）作为 YYCQ/YYCQ员工总数或规模；本公司侧锚定 excel「1.1信息-人员」70/61/33.15/45.85

### D. 体验 / Evidence

1. 主气泡完整可读；终稿来自 Hermes 合格正文（非短骨架糊弄）
2. coerce 骨架仅当 Hermes 正文**不可用**时的契约矫正；有更长合格过程稿时 `resolve`/finalize **必须选过程稿**；UI `replace_reply` 同步
3. Evidence Pack / prefetch **不得**长期 0% 却仍出硬数字骨架；MCP 证据须真实进入 Hermes 成稿；done.citations 应反映命中（非长期 0）

### E. 充分利用 Hermes 多轮 MCP（硬项）

适用范围：**kb_scope 非空 + native + deep + 人员横比**（P1 / CDP A3；矩阵 B/B+ 同口径）。

1. `hermes_orientg_kb_ask_calls >= 2`（至少：首轮取证 + 一轮核证/补缺），且 **全部发生在首轮 Runs 内**（非 retry 轮次）
2. MCP contract / instructions：即便 `evidence_sufficient=true`，仍要求 **对缺口维度或另一主体做一次核实 query**（query **不得**与首轮完全相同；对齐 loop guard「禁空转同 query」）
3. 核实后再写终稿；`next_action` 在待核证时为 `verify_gap_then_write_final`，核证完成后为 `write_final_answer_now`
4. **核证门闸 `want` 必须与实况一致**：需要核证时 `want=True`；不得在仍缺核实轮时日志 `want=False`
5. **极窄豁免**（须单测锁死，默认不适用 A3/P1）：
   - 非 `personnel_compare` 任务类型；或
   - 非 deep / 非 native 路径；或
   - 单主体非横比问句（无双实体横比意图）
   - **不豁免**：「证据已足写得好看」——仍须 ≥2 且 retry=0

`apply_personnel_structured_final_gate`：**仅异常保险丝**——合格或近似合格 **必须保留 Hermes 正文**。

## 2. Hermes 仓库运作原理（调研摘要）

> 来源：本机 `hermes-agent` v0.16.0 源码 + [API Server 文档](https://hermes-agent.nousresearch.com/docs/user-guide/features/api-server)

### 2.1 架构分层

```text
Orient-G backend
   POST /v1/runs  (stream: true, toolsets: ["orientg"])
    → Hermes Gateway (run_agent / Runs API)
        → LLM 多轮 tool round
        → tools/mcp_tool.py 调用 MCP stdio 子进程
            → orientg_server (FastMCP)
                → orientg_kb_ask → PostgreSQL KB
        → tool result JSON 注入 messages → 下一轮 LLM 成稿
  SSE: hermes.tool.progress / message.delta / run.completed
```

### 2.2 MCP 工具结果如何进入模型

`tools/mcp_tool.py::_make_tool_handler`：

1. MCP `call_tool` 返回 `content`（text blocks）+ 可选 `structuredContent`；
2. Hermes 包装为 `json.dumps({"result": text, "structuredContent": ...})` 作为 **role=tool** 消息；
3. **模型读的是 JSON 字符串**，不是 Orient-G 的 Python dict 原貌；
4. FastMCP 若返回 dict，通常序列化为 text JSON — 需在 **text 层**给出清晰中文行动指令 + 结构化块。

### 2.3 Tool loop guardrails（Hermes 侧）

`agent/tool_guardrails.py`：

- 默认 **`hard_stop_enabled=false`**：重复失败/无进展仅 **warn**，不 block；
- MCP 工具 **不在** `IDEMPOTENT_TOOL_NAMES` 默认集 → 重复 `orientg_kb_ask` 不会触发 idempotent_no_progress block；
- Orient-G 的 `HermesRunsLoopGuard` 是**网关侧**额外护栏（与 Hermes 独立）。

**含义**：Hermes 可以多次 kb_ask；Orient-G 应在 MCP 回复中明确「证据已足仍须不同 query 核证，再成稿」，并在 instructions 中强制**首轮即调 MCP + 人员深横比 ≥2 次**。

### 2.4 Runs API 关键字段

| 字段 | 作用 |
|------|------|
| `instructions` | 系统级编排约束（Orient-G 注入 orientg_* JSON + kb_ask hint） |
| `toolsets` | `["orientg"]` 限制仅 KB MCP（Tier 1/2 KB 任务） |
| `session_id` | 与 `hermes_session_key` / token bridge 对齐 |
| `stream_tool_progress` | 工具生命周期 SSE |

### 2.5 Orient-G 当前「限制层」清单

| 层 | 文件 | 对 Hermes 的影响 |
|----|------|------------------|
| 预检索 Evidence Pack | `agent_kb_prefetch.py` | 已有证据，仍要求再 MCP；**过早完整摘要会诱使空转** |
| Primer | `hermes_kb_mcp_bridge.py` | 故意不注入完整摘要 |
| Defer 过程稿 | `hermes_client.py` | 用户不见 Hermes 中间稿 |
| Tier policy | `agent_hermes_tier_policy.py` | min kb_ask、中文/禁 terminal |
| Loop guard | `hermes_runs_loop_guard.py` | 多次 kb_ask 无对照表 → abort |
| MCP retry | `hermes_client.py` | 首轮 0 MCP → 强制重试（**非理想常态；验收须=0**） |
| Supplemental | `agent_kb_supplemental.py` | Hermes done 后网关再搜 |
| Structured gate | `personnel_compare_report.py` | 覆盖 Hermes 终稿 |
| 质量择优 | `resolve_hermes_effective_reply` | 过程稿 vs completed 择优 |
| 核证门闸 | MCP reply / want 日志 | **须与实况一致**（缺核实轮时 want=True） |

## 3. 新 MCP 设计（agent-native v2）

### 3.1 原则

1. **证据 + 成稿契约一并返回**：不只给 excerpt dump，给 Hermes 明确的 `output_contract`；
2. **`evidence_sufficient: true` 只表示「够写表的证据在」——人员横比仍须核实轮**；
3. **结构化 `agent_payload`** 与 human `reply` 并存；
4. **中文 query 建议**内嵌 payload（含 `verification_queries`）；
5. **可推翻 legacy**：`HERMES_NATIVE_MCP_REPLY=true` 切换。

### 3.2 MCP 返回形状（v2 · 人员横比）

```json
{
  "ok": true,
  "reply": "（中文行动指令：已足仍须不同 query 核实 → 再成稿 + agent_payload + 证据节选）",
  "agent_payload": {
    "schema": "orientg_kb_ask_v2",
    "task_type": "personnel_compare",
    "language": "zh-CN",
    "entities": ["YYCQ", "可比公司A"],
    "evidence_sufficient": true,
    "verification_queries": ["YYCQ 2025 1.1信息-人员", "可比公司A 2025 销售人员 运营人员"],
    "output_contract": {
      "required_sections": ["### 人员结构对照", "### 对比分析", "### 口径说明"],
      "language": "zh-CN",
      "next_action": "verify_gap_then_write_final",
      "do_not": ["重复相同 query 检索", "英文 planning", "terminal/curl", "推算/推断/约N人"]
    }
  }
}
```

### 3.3 Native primer / 首轮 MCP / 多轮核证

当 `HERMES_NATIVE_MCP_REPLY=true`：

- Primer 文案改为 bootstrap 线索；
- instructions **硬性**：首轮必须调用 `mcp_orientg_orientg_kb_ask`；人员深横比 **至少 2 次**（取证 + 不同 query 核实）；
- **禁止**把可当终稿的对照表骨架 / Evidence Pack 全文过早注入过程流；
- 网关 `hermes_mcp_retry` 仅异常保险丝；验收计次，常态应为 0；**retry 路径不得标绿**。

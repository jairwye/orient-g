# 1.2.4 财务汇报与日程助理 — Implementation Plan

> **For agentic workers:** 实施编码前先 Read 设计规制；本文件为里程碑与验收拆解。  
> **本期（2026-10-13）已完成：** 仅规制 + 本计划落盘；**禁止**在「只写规划」任务中改业务代码。

**Goal:** 为财务部门提供自然语言日/周/月报（双端输入与双端展示）、部门周/月报提交管理层浏览、以及内网团队待办（Vikunja）；飞书日历深度集成与管理层问答后延。

**Architecture:** Orient-G KB 为汇报权威源；定稿镜像飞书云文档（策略 B）；财务汇报专用飞书机器人走同一编排契约 `draft → finalize → submit`；团队待办独立 Vikunja 容器。编排实现形态（Skill vs Workflow）在 1.2.4.a spike 锁定。

**Tech Stack（实施期）：** FastAPI、既有 KB ACL / MCP、Hermes Feishu Gateway、飞书 Open API（docx create/update）、Docker Compose、Vikunja、本地 LLM。

**Design spec:** [`specs/features/1.2.4-财务汇报与日程助理.md`](../features/1.2.4-财务汇报与日程助理.md)

## 1.2.4.a — 页面端汇报闭环 + 呈现

**Goal:** 书写人在 Orient-G 智能体完成个人日/周报与部门周报草稿→定稿；部门周报可提交；管理层在知识库浏览已提交材料。

### 任务

- [ ] **A1** 关闭 Spike S1，锁定编排形态
- [ ] **A2** 定义汇报元数据与 `draft | finalized | submitted`；可选 `work_report_index` + Alembic
- [ ] **A3** 实现 `save_draft` / `finalize`（先可无飞书，feishu 字段空）/ `submit` / `list`
- [ ] **A4** submit：校验部门授权；`allow_management`；审计日志
- [ ] **A5** 页面对话路径接通编排器（快捷提示：「写今日日报」「生成本周部门周报」「提交本周部门周报」）
- [ ] **A6** 管理层账号验收：仅 submitted 部门周报在约定文件夹 / ACL 下可读；书写人可读自己的草稿与定稿

### 验收

1. 财务测试账号对话生成个人日报并定稿 → KB 可见，`status=finalized`。
2. 汇总人生成部门周报并 submit → 管理层账号打开知识库可见；普通无管理层角色不可见该提交件（除非另有部门 ACL）。
3. 无飞书凭证时 finalize 仍成功，`feishu_sync_status` 为 skipped/failed 有明确语义。

---

## 1.2.4.b — 飞书云文档双展示

**Goal:** 定稿时同步 / 更新飞书云文档，对话返回飞书链接；与 KB 正文一致（允许格式差）。

### 任务

- [ ] **B1** 关闭 Spike S2；扩展 `feishu_sync`：create + update by `document_id`
- [ ] **B2** `finalize` 写入 `feishu_document_id` / `feishu_url` / `feishu_sync_status`
- [ ] **B3** `submit` 调整飞书文档权限或移动到管理层可见目录（策略写进运维文档）
- [ ] **B4** 同步失败可重试 API；UI / 对话提示可读
- [ ] **B5** 策略 B 回归：草稿阶段飞书侧无对应新文档

### 验收

1. 定稿后飞书打开链接可见正文；再次定稿更新同一文档 id。
2. 人为断开飞书 API：KB 定稿成功 + 失败状态 + 重试成功后状态恢复。

---

## 1.2.4.c — 财务汇报专用飞书机器人

**Goal:** 飞书单聊 / 群聊完成与页面等价的写报与定稿反馈；用户映射强制。

### 任务

- [ ] **C1** 创建独立飞书应用；凭证进密钥卷 / `.env`（不进 Git）
- [ ] **C2** Gateway 或后端按 bot 路由到 `work_report_orchestrator` only
- [ ] **C3** `feishu_open_id` ↔ Orient-G username 管理界面或配置；未映射拒绝写入
- [ ] **C4** 群聊体验：预览摘要 → 确认定稿 → 回飞书文档链接
- [ ] **C5** 多 bot 配置结构预留第二个占位（可空实现）

### 验收

1. 已映射用户在飞书完成个人周报定稿，与页面写入同一套 KB 记录。
2. 未映射用户收到拒绝说明，KB 无新草稿。
3. 该 bot 会话不能执行与汇报无关的危险 toolset（按 Hermes allowlist / 能力绑定检查）。

---

## 1.2.4.d — Vikunja 团队待办

**Goal:** 内网 Docker 运行 Vikunja；财务团队可共享项目、互相指派、看板查看、设截止日期；Orient-G 提供入口。

### 任务

- [ ] **D1** compose overlay：`vikunja` + 持久卷；仅内网暴露
- [ ] **D2** 运维文档：初始化管理员、邀请财务成员、推荐项目结构
- [ ] **D3** 前端入口：实用工具或侧栏「团队待办」→ Vikunja URL（外链优先，内嵌可选）
- [ ] **D4** （可选二期）Orient-G 用户与 Vikunja 账号映射 / OIDC
- [ ] **D5** 文档声明：与 `excel-kanban` 无关；飞书日历不在本里程碑

### 验收

1. 两名财务测试用户互相指派任务并在看板看到状态变化。
2. Orient-G 登录用户能从入口到达 Vikunja（网络策略允许范围内）。

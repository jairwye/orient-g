# 知识库 Tab UI 改造（方案 A 终稿）设计稿（v2）

日期：2026-04-27  
范围：Orient-G `frontend/app/knowledge/page.tsx`（优先），必要时扩展到 `frontend/app/components/`、`backend/routers/knowledge.py`（仅当确实需要）  
目标优先级：B（管得清）→ A（找得到）→ C（看得懂）

> 本设计稿是基于用户对现有 UI 的明确否定反馈重新脑暴后的“终稿 A”。核心原则：**极简层级、同一 frame 容纳所有知识库、去掉常驻右栏管理面板、所有管理动作回归 `⋯` 菜单、大 PDF 包管理以“产物弹层”承载**。

---

## 0. 关键结论（给评审的 30 秒版本）

- **页面不再出现“知识库”大标题层**与“文件浏览器”标题层：减少不必要的层级占用。
- **不同知识库（私人/公司公共/部门/项目）容纳在同一 frame**：用“范围 chips / 下拉”切换过滤，而不是分块并排占空间。
- **移除常驻右栏“管理面板/Inspector”**：管理动作统一进入三点菜单（文件夹 `⋯`、文档行 `⋯`）。
- **大 PDF 产物包管理改为顶栏入口 → 弹层（产物视角）**：弹层内是“包列表 + 行内导出类型 + `⋯` 菜单（下载/删除等）”的闭环。
- **修复/恢复失效的三点菜单**：至少恢复“新建文件夹”可用，确保能验证移动/复制/文件夹功能链路。
- **排序规则**：范围栏最上方固定“私人知识库、公司公共库”，其他保持现有排序。
- **默认文件夹落地**：在用户 `wangjia` 的“部门公共库”中应出现默认文件夹（“合同管理”或“合同台账”，以最终确认的名称为准）。

---

## 1. 背景与问题陈述（用户反馈映射）

### 1）多余层级导致不简洁
- **不需要“知识库”标题层**：Tab 已经是知识库语境。
- **不需要“文件浏览器”标题层**：重复占空间。
- **不需要把不同知识库拆成多块 panel**：同 frame 容纳即可。

### 2）意义不明/不应在此处出现的功能
- **“解析该文件夹”**：不应出现在知识库主 tab 的常驻 UI（至少不应作为显著按钮；可降级到 `⋯` 或单独工具页）。
- **右栏管理面板**：应移除，回归到 `⋯` 菜单与弹窗。
- **大 PDF 包管理**：应恢复为原有管理能力，但不能占用额外 panel；采用弹层承载。

### 3）失效功能阻塞验证
- “知识库旁三点菜单目前只有创建文件夹且失效” → 必须先修复，否则无法验证后续管理链路。

### 4）排序调整
- 私人、公司公共置顶；其他保持既有顺序。

### 5）未实现：部门公共默认文件夹
- 用户 `wangjia` 的部门公共库应出现默认文件夹（合同管理/合同台账）。

---

## 2. 成功标准（可验收）

### B：管得清（必须达成）
- **三点菜单可用**：文件夹 `⋯` / 文档行 `⋯` 至少包含并可执行关键动作（见 4.2/4.3）。
- **移动/复制可验证**：从“未归类文档”能移动/复制到任意文件夹；从某文件夹内能移动/复制到其他文件夹。
- **大 PDF 产物弹层闭环**：
  - 包列表可见（搜索/过滤可选）
  - 每行可选导出类型（Open-WebUI / cn_kb / standard）
  - 每行 `⋯` 菜单至少包含：下载、删除整个资源包

### A：找得到（下一阶段，但 UI 需预留）
- 顶栏全局搜索框（文档/文件夹/ID）。

### C：看得懂（下一阶段，但不阻塞）
- “进度/日志”从主界面移出：可在工具页或弹层内按需查看，不常驻占空间。

---

## 3. 非目标（明确不做）

- 不做常驻右侧 Inspector/管理面板（本轮强约束）。
- 不在主 tab 里放“解析该文件夹”的显著按钮（可降级到 `⋯` 或工具页）。
- 不引入复杂层级（多 panel 并排、重复标题条）。

---

## 4. 交互设计（终稿 A）

### 4.1 顶栏（单行工具条，无额外标题层）

顶栏元素（从左到右）：
- **范围切换**（chips 或下拉）：默认勾选“私人、公司公共”，可附加“部门、项目”
  - **排序**：私人、公司公共置顶；其他保持现有排序
- **全局搜索框**：placeholder `搜索文档/文件夹/ID`
- **上传**（主按钮）
- **新建文件夹**（次按钮）
- **大PDF产物**（次按钮，打开弹层）
- **全局 `⋯`**（可放少量次级入口，如“导入导出/设置”）

> 取消页面 H1 与“文件浏览器”标题；顶栏是唯一常驻“框架层”。

### 4.2 左侧：文件夹树（同 frame）

- 仅展示文件夹树（可折叠/搜索为后续增强）
- **每个文件夹行右侧 `⋯` 菜单**（B 优先）：
  - 新建子文件夹（可选）
  - 重命名
  - 分享/权限（如存在）
  - 删除文件夹

### 4.3 右侧：文档列表（同 frame）

列表列建议：
- 勾选框
- 名称
- 状态（可用/处理中/失败）
- 位置（所属文件夹/未归类）
- 更新时间
- 行 `⋯`

**文档行 `⋯` 菜单**至少包含：
- 移动到…
- 复制到…
- 删除（语义明确：在文件夹上下文则“从文件夹移除”，在未归类/全局则“彻底删除”）

### 4.4 大 PDF 产物弹层（产物视角）

入口：顶栏按钮 **大PDF产物**。

弹层内容：
- 包列表（支持搜索包名/package_id）
- 每行：
  - 包名、状态、来源文件夹、创建时间
  - **行内导出类型**（用户选择）：Open-WebUI / cn_kb / standard
  - **行内 `⋯` 菜单**（收起动作）：
    - 下载（按当前行导出类型）
    - 删除整个资源包（含磁盘产物）
    - （可选）打开工具页定位

> 解释：产物视角只关心“可下载/可删除/可导出”，过程进度可跳转工具页，不在主界面常驻。

---

## 5. 失效功能修复（优先级最高）

### 5.1 “新建文件夹”必须可用
该功能一旦失效，会阻断后续验证：
- 不能验证文件夹增删改
- 不能验证文档移动/复制到文件夹

验收：点击“新建文件夹”创建成功，列表/树立刻可见，且三点菜单动作对新文件夹生效。

---

## 6. 默认文件夹（wangjia 部门公共库）

目标：在用户 `wangjia` 的“部门公共库”里出现默认文件夹：
- 名称二选一：**合同管理 / 合同台账**（以最终确认的名称为准）

实现边界（不在此稿决定具体实现方式）：
- 可由后端在用户首次访问/首次加载 folders 时兜底创建
- 或由前端在 folders 加载后触发一次“若不存在则创建”
- 需要遵守：共享可见范围下的“同名不可创建”规则

验收：切到部门公共范围后能看到该默认文件夹。

---

## 7. 与现实现状的冲突点（本次重做的关键）

- 需要移除/回滚：常驻右栏 Inspector（管理面板）相关 UI。
- 需要移除/降级：文件夹“解析该文件夹”显著按钮（若仍存在）。
- 需要恢复：大 PDF 包管理能力（但改成弹层承载）。

# 知识库 Tab UI 改造（方案 1）设计稿

日期：2026-04-27  
范围：Orient-G `frontend/app/knowledge/page.tsx`（优先），必要时扩展到 `frontend/app/components/` 与后端权限/分享接口  
目标优先级：B（管得清）→ A（找得到）→ C（看得懂）

---

## 背景与问题陈述

当前知识库 Tab 的功能点齐全但“管理体验”仍偏碎片化，典型问题：

- **分享/权限不够一等公民**：用户难以快速理解“谁可见/谁可写/如何回收分享”，尤其涉及部门/项目/公司等范围时。
- **批量操作入口不统一**：批量移动/复制/删除等动作需要更明确的语义与更低误操作率。
- **文件夹归类缺少清晰路径**：不做拖拽的前提下，需要统一的“移动到…/复制到…”能力，且能跨知识库范围选择目标文件夹。
- **状态与任务可见性不足**：解析/索引等后台动作应能在右侧面板里查看、重试，而不是散落在日志或隐式轮询里。

本设计采取“方案 1（最小改动）”：保留现有双栏页面骨架，集中把“管理体验”打磨到位。

---

## 成功标准（可验收）

### B：管得清（必须达成）
- **右侧面板（Inspector）成为统一管理入口**：单选=详情，多选=批量面板；未选中=空状态提示。
- **权限模型清晰**：两层模型
  - **可见范围**：kb_kind（私人/部门/项目/公司）+ 具体范围（department_ids / project_ids / company_public）
  - **角色**：viewer / editor / admin（3 档）
- **回收分享一等公民**：
  - 默认动作：一键全撤（回到私人）
  - 高级动作：按范围撤回（部门/项目/公司可逐条撤）
- **归类不靠拖拽也顺手**：统一“移动到…/复制到…”弹窗，可搜索目标文件夹。
- **删除语义不含糊**：
  - 文件夹上下文：默认“从该文件夹移除”
  - 未归类/全局上下文：默认“彻底删除”，且明确二次确认提示

### A：找得到（下一阶段）
- 全局搜索与筛选 chips（全部/处理中/可用/失败），优先覆盖“快速定位与治理”场景。

### C：看得懂（下一阶段）
- 右侧面板可查看解析/索引日志，能一键重试；后台任务条明确展示进行中任务。

---

## 非目标（本轮明确不做）
- 不做拖拽（文档拖到文件夹、文件夹层级拖拽、排序拖拽）。
- 不做“单文档独立授权”（避免权限碎片化）；权限以“文件夹”作为最小授权单元。
- 不引入复杂 RBAC/多角色矩阵；最小 3 角色模型。

---

## 总体方案（方案 1：保留双栏骨架）

### 页面骨架（保持现有结构）

- 继续使用当前双栏布局：`md:grid-cols-2`
  - **左栏**：文件浏览器（未归类文档 + 知识库/文件夹树）
  - **右栏**：Inspector（默认空状态；选中后展示详情或批量面板）

#### 右栏默认空状态（已确认）
- 未选中任何文档：显示提示卡片
  - 文案：`选择一条文档查看详情；或勾选多条进行批量操作。`
  - 可选快捷入口（后续 A/C）：搜索提示、查看后台任务

---

## 关键交互设计（B：管得清）

### 1) 批量操作（右侧批量面板）

#### 触发
- 任意列表（未归类/文件夹内）勾选文档数量 ≥ 1。
- 跨上下文勾选（未归类 vs 某文件夹）时：自动清空旧选择再开始新选择（避免语义不清）。

#### 右栏批量面板内容
- 顶部：
  - `已选 N 条`
  - 操作：`清空选择`
- 中部：
  - 折叠的已选清单（仅显示：名称、状态、位置）
- 底部：批量操作按钮（按权限显示或禁用）
  - **移动到…（必做）**
  - **复制到…（必做）**
  - **删除（必做，二次确认）**
  - 重新解析/重试（C 阶段可增强）

#### 删除语义（已确认）
- **文件夹上下文**：删除=“从该文件夹移除”  
- **未归类/全局上下文**：删除=“彻底删除”  
均需二次确认，确认弹窗明确提示影响范围与不可逆性。

---

### 2) 文件夹归类（不做拖拽，统一弹窗）

#### “移动到…”/“复制到…”弹窗（统一复用：单条与多条）
- 目标选择区：
  - kb_kind 分组：私人/部门/项目/公司
  - 文件夹列表：支持搜索；可选“最近使用”
- 确认区：
  - 文案：`将把 N 条文档移动到 <folder>` / `复制到 <folder>`
- 错误处理：
  - 目标不可写：按钮禁用 + 提示原因
  - 目标同名冲突：提示并给出策略（后续可加：保留两份/覆盖/跳过）

---

### 3) 分享/权限（两层模型 + 回收分享）

#### 授权粒度
- **只对文件夹授权**，文档默认继承文件夹权限；不支持单文档独立授权（已确认）。

#### 权限面板入口
- 文件夹 `⋯` 菜单：`分享/权限…`
- （可选）未来支持“选中文件夹”时：右栏可进入同一面板

#### 权限面板结构

**（A）可见范围（Scope）**
- 当前文件夹已共享到的范围（只读展示 + 管理员可编辑）
  - 私人（始终存在）
  - 部门：`department_ids[]`
  - 项目：`project_ids[]`
  - 公司公共：`company_public` 开关

**（B）角色（Role）**
- 对“可见范围集合”统一采用 3 角色：
  - viewer：只读
  - editor：可上传/移动/复制/重试解析（不含分享与删除）
  - admin：含分享/回收分享/删除

> 说明：角色只影响“可写/可管理”的操作；可见性由 scope 决定。

**（C）回收分享（Revoke）**
- 主按钮：**一键全撤**（撤回所有非私人共享）
- 高级展开：按范围逐条撤回（部门/项目/公司可分别撤）

#### 权限展示文案（减少误解）
- `分享的是文件夹（包含其内文档）。文档默认继承文件夹权限。`

## 组件与状态边界（实现导向）

本设计不要求一次性拆分大量组件，但建议逐步收口：

- `KnowledgePage`：保留数据加载与顶层状态（folders、folderDetails、bulkSelection、openMenu 等）
- `InspectorPanel`（建议新增）：右栏统一承载
  - `EmptyState`
  - `DocDetailPanel`（单选详情，后续加 tabs）
  - `BulkPanel`（批量面板）
  - `FolderAclPanel`（分享/权限）
- `MoveCopyModal`（建议抽出）：移动/复制弹窗统一复用

## 风险与缓解
- **权限语义变更风险**：先以“展示清晰 + 按现有后端能力落地”为原则；若后端暂不支持 role，则 UI 先按“规划态”展示并标注“后端未启用”。
- **误删风险**：删除语义分上下文 + 二次确认 + 明确提示影响范围。
- **后续扩展风险**：保持 Inspector 为统一入口，避免再次把动作散落到多处。

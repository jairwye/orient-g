## 2. 信息架构（与原型图一致）

### 2.1 顶栏（一行）

从左到右：

1. **搜索框**（占宽优先）
2. **范围 chips**：私人 / 部门公共 / 项目公共\* / 公司公共（默认全选存在的四项）
3. **带到 AI 互动**
4. **大 PDF 文档包**（切换右栏整体为文档包面板，行为沿用 v3：右栏替换，底部日志独立）

\*「项目公共」：仅当后端元数据与用户权限表明存在该项目公共入口时渲染 chip；不存在则不占位。

### 2.2 主区（两列）

**左栏（文件夹树）**

- 按可见 `kb_kind` 分组。
- 每组第一行：**可选中的知识库头**（表示选中整个知识库，不等价于选中某个文件夹）。
- 其下：**仅文件夹列表**（可滚动）。
- **不再展示**私人根级「零散文档」行。

**右栏（上下文）**

- 顶部：**当前所属知识库** + **KB 大菜单按钮**（创建文件夹、刷新列表等库级动作）。
- 中部上下分区：
  - **文档（上）**：根级文档或当前文件夹内文档表。
  - **文件夹（下）**：当前知识库下文件夹清单（私人根级时列出私人文件夹；选中某文件夹时仍可在下方展示「子层级」若未来有；当前数据结构多为扁平则列出同级文件夹）。

## 3. 选择与状态模型（实现要点）

用单一 discriminated union 表达选中态，避免 `activeFolderId` 与其它语义打架：

```ts
type KbSelection =
  | { kind: "kb"; kb_kind: string }
  | { kind: "folder"; kb_kind: string; folder_id: string };
```

- 选中 KB：`kind='kb'` → 右栏显示 KB 管理 + 文档区显示根级文档 + 文件夹区列出该 KB 下文件夹。
- 选中文件夹：`kind='folder'` → `loadFolderDetail(folder_id)`，文档区绑定文件夹文档。

## 4. 「合同管理」加载失败（验收）

- UI：错误提示必须包含后端 `detail`（若有）。
- 技术：核对 folder_id、403、404、JSON 解析；必要时打印 request id（如有）。
- 回归：选一个已知存在的私人文件夹应 **必成功**；失败则阻塞发布。

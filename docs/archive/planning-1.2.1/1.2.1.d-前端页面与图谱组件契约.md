# 3.d 股权全景结构化：前端页面与图谱组件契约

## 范围
- 定义 Next.js 前端的页面结构、图谱组件数据契约与交互要求。
- 前端只依赖后端标准 JSON 输出（`nodes/edges/params/stats`），不直接耦合数据库结构。

## 交付物
- 页面路由与信息结构（目标列表、公司详情图谱、分析页）。
- 图谱组件输入契约（nodes/edges）与交互要求。
- 性能与截断 UX 口径（与 `3.c` 的 `stats.truncated` 对齐）。

## 页面结构建议
- `/analysis`：股权全景工作台（推荐作为总入口）
  - 地区/行业/主体类型分布（对接 `/api/analysis/summary`）
  - 关键指标卡：覆盖率、异常数、循环持股数、平均深度/节点数、截断比例（可分阶段补齐）
  - 点击分布项联动跳转到 `/targets` 并带筛选条件
- `/targets`：目标公司总览
  - 搜索/筛选：地区、行业、是否境外、是否国资、是否上市（可按数据可用性裁剪）
  - 指标卡（可选）：上游最大深度、下游节点数、Top 持股（如已计算）
  - 点击进入公司详情页
- `/targets/[id]`：公司详情
  - Tabs：`上游股东` / `下游投资`
  - 参数控件：`min_pct`（默认 0.2）、`max_depth`、`max_nodes`
  - 左侧图谱，右侧主体详情侧栏（hover/click node）
  - 操作：导出当前子图（nodes/edges JSON；如图谱库支持可导出 SVG/PNG）
  - 解释面板（强烈建议）：Top 持股路径/关键终点类型/截断原因解释（让“图”变成“结论”）
- `/compare`（或 `/analysis/compare`）：公司对比（强烈建议）
  - 选择公司 A 与 B
  - 输出共同股东/共同被投、结构差异、境外链路差异、循环风险差异
  - 支撑汇报/研判场景

## 图谱组件数据契约（必须对齐 `3.a/3.c`）
前端图谱组件仅依赖后端返回的标准 JSON：
- `nodes[]`: `{id,name,entity_type,credit_code,tags,geo,industry}`
- `edges[]`: `{id,from,to,hold_pct,hold_pct_text,source}`

## 交互要求（建议作为验收口径）
- 节点样式：按 `entity_type` 映射颜色/形状（公司/自然人/境外/基金等可区分）
- 边样式：按 `hold_pct` 映射粗细；未知比例用默认样式
- 悬浮提示：
  - 节点：`name`、`entity_type`、`credit_code`（如有）
  - 边：`hold_pct_text`（优先）或 `hold_pct`
- 点击节点：右侧侧栏拉取 `/api/entities/{id}` 更新详情
- 解释面板（若启用）：
  - 展示 3 条“最关键路径”（上游控制/下游投资）与关键节点标签（国资/上市/境外/基金/自然人）
  - 当 `stats.truncated=true` 时，解释截断发生原因与建议调参策略

## 性能与截断 UX（必须可验收）
- 默认参数建议：`max_nodes=500`、`max_depth=3`（可按实际性能调整）
- 当后端返回 `stats.truncated=true`：
  - 页面必须显式提示“已截断”，并展示 `truncate_reason`（可本地映射为中文说明）
  - 提供操作引导：可提高 `max_nodes/max_depth` 或收紧 `min_pct` 以控制规模
- 导出（建议）：
  - 下载“当前子图复现包”：至少包含 `snapshot_name + params + nodes/edges + stats(truncated)`

## 验收标准（本步）
- 全景工作台：
  - 能展示 `/api/analysis/summary` 的地区/行业/类型分布
  - 点击分布项可联动到 `/targets` 列表筛选
- 目标列表页能展示目标公司，并可搜索定位公司进入详情页。
- 公司详情图谱页：
  - `direction=up/down` 可切换
  - `min_pct/max_depth/max_nodes` 改变会触发重新查询并可复现变化
  - 命中截断时，UI 明确提示并引导用户调整参数
- （若实现对比页）公司对比页能输出共同股东/共同被投与差异指标

## 风险与依赖
- 依赖 [`3.c`](规划/3.c_3.0-后端API契约与查询参数.md) 返回统一 `stats.truncated/truncate_reason`，否则前端无法做稳定的截断提示与性能兜底。

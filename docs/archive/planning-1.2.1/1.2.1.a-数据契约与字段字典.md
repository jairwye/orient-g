# 3.a 股权全景结构化：数据契约与字段字典

## 范围
- 定义股权全景所需的**标准化数据结构**，用于导入、存储、API 输出与前端渲染保持同一口径。
- 本规划只规定字段字典、约束与消歧原则；具体实现（脚本/人工清洗/工具链）由 [`3.b`](规划/3.b_3.0-导入流程与数据清洗规范.md) 规定流程。

## 交付物
- 标准化文件：`entities.csv`、`equity_edges.csv`（可选 `targets.csv`）字段字典与必填/建议约束。
- 主体唯一键与消歧规则（含冲突输出要求）。
- 对外 JSON（图谱接口）标准输出形态：`nodes[]/edges[]/stats`。

## 1) `entities.csv`（主体维表）
每行一个主体（公司/自然人/机构等）。

### 必填字段
- `snapshot_name`：批次名（例：`2026-04-08_run1`）
- `name`：主体名称（公司全称/自然人姓名/机构名称）
- `entity_type`：主体类型（建议枚举：`company|person|gov|fund|overseas|other`）

### 强烈建议字段
- `credit_code`：统一社会信用代码（自然人/境外通常为空）
- `province` / `city` / `district`：注册地（可空）
- `industry`：行业（平台口径原样 + 可选映射）
- `status`：存续状态
- `established_date`：成立日期（YYYY-MM-DD）
- `is_listed`：是否上市（true/false/空）
- `is_state_owned`：是否国资（true/false/空）
- `is_overseas`：是否境外（true/false/空）
- `source_url`：来源 URL（如有）
- `raw_source`：可选，原始字段 JSON 字符串（调试/追溯用）

### 唯一键与消歧（必须可追溯）
- **优先级 1**：`credit_code` 一致 → 视为同一主体。
- **优先级 2**：信用代码缺失时，用 `name + province/city + established_date` 作为候选匹配键。
- **仍无法判断**：必须输出到 `conflicts/`（详见 `3.b`），并给出处理结论后再入库/回填。

## 2) `equity_edges.csv`（股权边表）
每行一条“股东 → 被投公司”的股权关系。

### 必填字段
- `snapshot_name`
- `from_name`：股东名称
- `to_name`：被投公司名称

### 强烈建议字段
- `from_credit_code`：股东信用代码（若股东为公司）
- `to_credit_code`：被投公司信用代码（强烈建议）
- `hold_pct`：持股比例（0~100 数值；未知留空）
- `hold_pct_text`：原始文本（例：`20%-30%` / `未公示`）
- `source_platform`：来源平台（默认 `tianyancha`）
- `source_doc`：导出文件名/报告编号（追溯）
- `collected_at`：采集/导出日期时间（可用导出日期）

### 规则
- `hold_pct` 与 `hold_pct_text` 至少保留一个；区间与不可解析优先写入 `hold_pct_text`。
- 同一 `from -> to` 多条记录：
  - 若比例与来源均相同可去重；
  - 若比例/来源不同可保留多条，并在后端选择展示优先级（不在本规划限定算法，但必须可复现）。

## 3) `targets.csv`（30 家目标公司清单，可选）
用于标记本批次的“目标公司集合”。

字段建议：
- `snapshot_name`
- `name`
- `credit_code`（建议）
- `alias`（可选）
- `is_key`（true/false，可选）
- `notes`（可选）

## 4) 后端对外 JSON（图谱接口标准输出）
为前端图渲染，后端统一输出（字段最小集合，允许扩展但不破坏兼容）：

```json
{
  "snapshot": {"id":"...","name":"2026-04-08_run1"},
  "params": {"direction":"down","min_pct":0.2,"max_depth":3,"max_nodes":500},
  "nodes": [
    {
      "id":"uuid",
      "name":"某某有限公司",
      "entity_type":"company",
      "credit_code":"...",
      "tags":{"is_state_owned":false,"is_overseas":false,"is_listed":false},
      "geo":{"province":"北京","city":"北京"},
      "industry":"..."
    }
  ],
  "edges": [
    {
      "id":"uuid",
      "from":"uuid",
      "to":"uuid",
      "hold_pct":25.0,
      "hold_pct_text":"25%",
      "source":"tianyancha"
    }
  ],
  "stats": {
    "node_count": 123,
    "edge_count": 140,
    "depth_max": 4,
    "truncated": false,
    "truncate_reason": null
  }
}
```

约束：
- `params.min_pct/max_depth/max_nodes` 必须在后端/前端/QA 三处同一口径（见 `3.0` 与 `3.e`）。
- 当发生截断时：`stats.truncated=true`，并给出可解释的 `truncate_reason`（例如 `max_nodes_exceeded`）。

## 验收标准（本步）
- 能用本文件字段字典产出一份 1~2 家公司小样 CSV：
  - `entities.csv` 去重/消歧可追溯（冲突能落到 `conflicts/`）
  - `equity_edges.csv` 的 from/to 均可关联到主体（至少在小样范围内）
- 图谱 JSON 输出形态对齐：前端仅依赖 `nodes/edges/params/stats` 即可渲染基本图。

## 风险与依赖
- 依赖 `3.b` 的清洗流程把“消歧与冲突处理”落地，否则会出现 API 查询空洞或重复边爆炸。

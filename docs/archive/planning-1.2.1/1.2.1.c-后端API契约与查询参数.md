# 3.c 股权全景结构化：后端 API 契约与查询参数

## 范围
- 定义 FastAPI 对外提供的最小接口集合与请求/响应契约，供前端页面直接调用。
- 所有接口默认按 `snapshot_name` 过滤，保证批次隔离与可复现。

## 交付物
- MVP 路由清单与请求参数（含 `direction/min_pct/max_depth/max_nodes`）。
- 标准响应 JSON：图谱 `nodes/edges/params/stats`（与 `3.a` 保持一致）。
- 截断策略的对外表达（响应字段与提示口径）。

## 约定（必须全链路一致）
- `snapshot_name`：必填（或有默认值，但必须在响应中回传）。
- `min_pct`：下游阈值，默认 **0.2**（20%）。
- `max_depth/max_nodes`：扩张控制，默认值由实现决定，但必须对外可见且可修改。

## 1) 目标公司
### `GET /api/targets?snapshot_name=...`
返回本批次的目标公司集合（默认 30 家）。

Response（示例）：
```json
{
  "snapshot": {"name":"2026-04-08_run1"},
  "items": [
    {"entity_id":"uuid","name":"某某公司","credit_code":"...","alias":null,"is_key":false}
  ]
}
```

## 2) 主体搜索
### `GET /api/entities/search?snapshot_name=...&q=...&limit=20`
按名称/信用代码模糊搜索，用于前端定位与跳转。

Response（示例）：
```json
{
  "items": [
    {"id":"uuid","name":"...","credit_code":"...","entity_type":"company","province":"...","city":"..."}
  ]
}
```

## 3) 主体详情
### `GET /api/entities/{entity_id}?snapshot_name=...`
返回主体画像字段（用于侧栏/信息卡）。

Response（示例）：
```json
{
  "id":"uuid",
  "name":"...",
  "credit_code":"...",
  "entity_type":"company",
  "geo":{"province":"...","city":"...","district":null},
  "industry":"...",
  "status":"...",
  "tags":{"is_listed":false,"is_state_owned":false,"is_overseas":false}
}
```

## 4) 股权图谱展开（核心）
### `GET /api/graph/ownership?snapshot_name=...&target_entity_id=...&direction=down&min_pct=0.2&max_depth=3&max_nodes=500`
返回用于图谱渲染的 `nodes/edges`。

规则建议（作为验收口径）：
- `direction=up`：沿 `equity_edges(from -> to)` 反向找上游股东
- `direction=down`：沿 `equity_edges(from -> to)` 正向找下游投资
- 当 `direction=down` 时：**仅对 `hold_pct >= min_pct*100` 的边继续递归**
  - 注：是否“显示所有边但只递归满足阈值的边”由实现决定，但必须在响应 `stats` 明确策略与截断原因

Response：见 [`3.a`](规划/3.a_3.0-数据契约与字段字典.md) 的 JSON 模板（必须包含 `params` 与 `stats.truncated`）。

### 截断提示（必须可验收）
当命中 `max_depth/max_nodes` 时：
- `stats.truncated=true`
- `stats.truncate_reason` 给出枚举原因（如 `max_nodes_exceeded|max_depth_reached|safety_guard`）
- 如可行，返回 `stats.node_count/edge_count/depth_max` 以便前端提示“当前展开规模”

## 5) 统计汇总（MVP）
### `GET /api/analysis/summary?snapshot_name=...`
返回总体分布统计（地区/行业/主体类型/终点类型等）。

Response（示例）：
```json
{
  "snapshot":{"name":"2026-04-08_run1"},
  "distributions":{
    "entity_type":{"company":1234,"person":88,"overseas":12},
    "province":{"北京":120,"上海":80}
  }
}
```

## 5.5) 导出与下载（推荐补齐，形成“可复现分析包”）
> 本部分用于支撑 `3.0` 中“导出/下载”的最终成果形态；若只做最小 MVP，可先实现“当前子图导出”。

### `GET /api/export/subgraph?snapshot_name=...&target_entity_id=...&direction=...&min_pct=...&max_depth=...&max_nodes=...`
导出“当前参数下的子图”，用于复现与归档。

Response（建议）：
- 复用图谱响应结构（见 `3.a`），并增加可选元信息：
  - `exported_at`
  - `export_id`（便于前端下载命名与审计）

### `GET /api/export/csv?type=entities|equity_edges|targets&snapshot_name=...`
下载标准化 CSV（以批次为单位）。

说明：
- `type=targets` 若未启用 targets 表可返回 404/空文件，但需明确提示。

### `GET /api/export/qa_report?snapshot_name=...`
（可选增强）导出 QA 报告包（异常清单 + 汇总），用于验收归档与问题定位。

## 6) 模式/聚类结果（可后置）
### `GET /api/analysis/patterns?snapshot_name=...`
返回聚类标签、典型架构模板命中、每个簇的代表公司列表（可后续实现）。

Response（示例）：
```json
{
  "snapshot":{"name":"2026-04-08_run1"},
  "clusters":[
    {"cluster_id":"C1","label":"多层控股+境外节点占比高","members":[{"entity_id":"uuid","name":"..."}]}
  ],
  "rules":[
    {"rule_id":"R_overseas_layer","hit_targets":[{"entity_id":"uuid","name":"..."}]}
  ]
}
```

## 7) 公司对比（强烈建议，体现“全景”价值）
### `GET /api/analysis/compare?snapshot_name=...&entity_id_a=...&entity_id_b=...&min_pct=0.2&max_depth=3&max_nodes=500`
返回两家公司对比结果，用于前端 `/compare` 页面。

Response（建议最小形态）：
```json
{
  "snapshot":{"name":"2026-04-08_run1"},
  "params":{"min_pct":0.2,"max_depth":3,"max_nodes":500},
  "a":{"entity_id":"...","name":"..."},
  "b":{"entity_id":"...","name":"..."},
  "overlap":{
    "common_shareholders":[{"entity_id":"...","name":"..."}],
    "common_investments":[{"entity_id":"...","name":"..."}]
  },
  "diff_stats":{
    "a_node_count": 120,
    "b_node_count": 80,
    "a_overseas_ratio": 0.12,
    "b_overseas_ratio": 0.03,
    "a_cycle_count": 1,
    "b_cycle_count": 0
  }
}
```

## 验收标准（本步）
- `/api/targets` 能返回本批次目标公司集合，且每项能关联到 `entity_id`。
- `/api/entities/search` 支持按名称与信用代码检索，且 `limit` 生效。
- `/api/graph/ownership`：
  - `direction=up|down` 均可返回
  - `min_pct` 提高时，下游递归节点数可复现减少
  - `max_depth/max_nodes` 生效，且能通过 `stats.truncated` 验收截断提示
- （若实现导出）导出接口：
  - `export/subgraph` 的输出可直接用于前端“下载并复现”
  - `export/csv` 能按 `snapshot_name` 正确下载

## 风险与依赖
- 依赖 `3.a/3.b` 的主体消歧质量；否则 graph 查询会出现“断边/孤点/重复点”导致体验与统计失真。
